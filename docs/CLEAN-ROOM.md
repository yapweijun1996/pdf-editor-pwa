# License and provenance policy

`docs/CLEAN-ROOM.md` is a compatibility path, not a blanket source-reading restriction. This policy applies to project-authored modules, fixture recipes, generated corpus artifacts and measurement tooling. It follows [ENGINE-PLAN.md](../ENGINE-PLAN.md) at `bcfda7a` and the [owner's Phase 0 amendment](notes/sources.json). The original Phase 0 work used a stricter source-access workflow. That restriction is historical, not current policy, and prior [review evidence](provenance/reviews/phase0-review.md#research-deliverable) applies only to the recorded work.

## Inputs and handoff

- For our own modules, start with public specifications and independently written behavior notes, then design and implement from those requirements. Public documentation, observed behavior and permitted public source may inform research. Record the version or edition, URL or location, section or other locator, consultation date and purpose. Public access alone does not grant reuse or redistribution rights. Do not import specification examples or PDFs into the corpus.
- You may read license and notice files for verification, and read permissively licensed dependency source to understand behavior, debug a dependency, or audit it. This does not authorize copying, translating or porting third-party code into our modules, even if it is permissively licensed or appears in tests, documentation, search results or AI output. Do not use GPL, AGPL, unlicensed, unknown-license or other disallowed implementation material as the basis for our modules.
- Research hands off independently written behavior notes, source references, fixture expectations and limitations. Implementers record their own sources. If disallowed material may have influenced the work, stop on the affected scope, quarantine suspect notes without forwarding excerpts, record the exposure and scope, and refer it to an independent reviewer for disposition, reassignment or re-derivation. Do not self-clear.

## Black-box measurement protocol

Run a pinned installed reader or validator through documented public UI/CLI interfaces on synthetic files. Record version, settings, input hash and sanitized observations (open status, counts, visible features, check diagnostics). Use no private APIs, implementation internals or source-bearing logs as measurement inputs. Keep files local. The specification and fixture recipe define expected behavior; differences between tools are findings, not new requirements. Do not use oracle output PDFs as source fixtures or the app's own renderer as its second reader. This protocol defines measurement evidence; it does not prohibit separate permitted debugging or audits.

## Licensing and provenance gates

- A dependency is not our implementation. Depending on, bundling or vendoring verified MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause or ISC material is allowed. Retain applicable licenses and notices in the repository and list bundled material in `THIRD-PARTY-NOTICES`. Keep dependencies unmodified where possible and document patches. pdf-lib and PDF.js (`pdfjs-dist`) stay; retaining them does not clear every bundled asset for release.
- GPL, AGPL, unlicensed or unverifiable material, and restrictive source-available or non-commercial licenses are barred. LGPL is not on the allowlist: reject it by default, with no use absent an explicit documented compatible disposition under the plan. The plan bars LGPL use that imposes obligations on our code. A package-level license or a license exception does not by itself clear separately licensed files.
- Generate fixtures independently, including their text, art, samples and ancillary inputs. Record artifact hashes, generation recipe, inputs and rights-holder CC0-1.0 dedication; a license label alone is not a dedication. No downloaded PDF specimens. Do not dedicate material we do not control.
- Keep a [provenance record](provenance/README.md) per authored module. An independent engineer reviews the exact recorded revision, including source eligibility and attribution, independent derivation and file digests. Authors do not sign their own provenance, QA or security gates. Before each release, a reviewer who did not introduce the dependency audits each bundled file's name, version, license, origin, retained notices and any patches; provenance and similarity checks do not substitute for this audit. QA retains blocker/minor/cosmetic classifications; only blockers fail a QA round.

## Mechanical similarity review (no third-party source disclosure)

The comparator's isolation and output restrictions are safeguards for running this tool, not rules against separate permissible source reading.

1. A non-author review operator pins the candidate revision, authored code file list, bundled comparator inventory (versions and digests), comparator tool/version and settings. The operator grants read-only access to an isolated, local comparator process, not to researchers, implementers or reviewers. No uploads, source browsing or interactive side-by-side diff. This is a separate release workflow, not a Phase 0 research action.
2. Compare exact file hashes and mechanically compare token windows or fingerprints for near matches. Record tokenizer/normalization, window size and alert threshold before scanning; do not report a skipped language or unreadable file as clear. Verify coverage and positive/negative controls using synthetic examples. Keep source-bearing intermediates and tool stderr quarantined; disable snippets, raw tokens, stack traces and source-bearing output before the run. If tool output cannot be safely filtered, stop and report blocked.
3. Export only an allowlisted summary: revision, tool/setup, inventories or their IDs/digests, coverage, counts, match IDs, authored paths/ranges, opaque comparator IDs and scores, omissions and verdict. No third-party snippets or reversible fingerprints. A reviewer checks matches using only authored material and documented spec constraints or boilerplate; log the disposition by match ID. Unresolved material similarity or incomplete coverage blocks clearance. If needed, commission an independent rewrite from recorded allowed inputs, then rerun. A clear report is evidence, not proof of independent authorship.
4. Retain the sanitized report along with the provenance and license-audit evidence. No author clearance, no rubber-stamping absent evidence, and no carry-over across changed inputs. This policy defines the protocol; it does not claim a scan or approval occurred.
