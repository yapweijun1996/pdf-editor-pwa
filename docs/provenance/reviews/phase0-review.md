The launcher writes `docs/provenance/reviews/phase0-similarity.json` atomically at a fixed path. Exit 0 means complete coverage within the stated scope with no hits, 2 means a blocked scan or hits requiring disposition, and 1 means no report from this invocation (do not use a stale report). The report pins launcher, worker, parser, base revision and the actual file bytes checked; `head` is the underlying commit, not the identity of uncommitted files. Compare the sanitized report twice on a frozen tree before relying on it. Run against the exact handoff candidate again if any code, comparator or evidence changes.

- Inventory: Git's path-only diff from `bcfda7a`, plus unignored new files, for `.js`, `.mjs` and `.cjs`. Untouched existing app JS is not authored code. It is byte-checked, not used for comparison. Git-ignored scratch, embedded scripts, other languages, maps and WASM are not tokenized. Confirm the inventory against Phase 0 provenance before signing. Comparator IDs are deterministic ordinals over sorted current and baseline `vendor/` JS paths; no comparator paths are exported. SHA-256 and byte/token counts distinguish exact inputs.
- Rules: whole-file SHA-256 equality plus every contiguous 80-token window, zero-based positions. TypeScript parses UTF-8 without evaluation, handling regex and template contexts. Whitespace and comments disappear; identifier and literal spelling/value disappear into token kinds; operators, keywords, delimiters and literal classes remain. A rolling 32-bit prefilter is verified by comparing all 80 normalized kinds; no hashes of token sequences are exported. Report one deterministic witness per matched file pair, prioritizing whole-file matches. No hits cannot prove authorship; shared long syntax can collide structurally and changes to punctuation, order, control flow, minifier rewrites, short copies, or translated code can escape detection.
- The comparator runs in a separate local Node permission-mode child with explicit read paths, no ordinary network, spawn or file-write permissions, an empty environment, and no evaluator or source execution. This is a trusted-code permission boundary, not a general malware sandbox. The parent discards stderr, validates and reconstructs an allowlisted report, and does not display raw child output. Parser diagnostics, token sequences, excerpts and vendor paths are not emitted. Limits include 8 MiB per input (16 MiB for the pinned parser), 700,000 tokens per code file, five million indexed candidate comparisons, a 384 MiB V8 old-space limit, 45 s and 1 MiB output. A timeout, input rejection, parser failure or other omission cannot produce a clear verdict. The working tree must be frozen; this is not a filesystem snapshot against concurrent writes.
- Runtime check compares each raw working-tree blob to the Git blob identity from `bcfda7a` and checks that no extra runtime files exist under the contract paths. A separate raw SHA-256 inventory digest matches the harness convention (sorted `[path, sha256]` pairs). An empty Git filename diff alone is not the byte-equality evidence.
- Controls run on each invocation: a long renamed/minified synthetic copy, unrelated long code and short code, a byte-identical copy, and rejection of invalid syntax. The separate test exercises an unreadable input, mismatched runtime bytes and a wrong parser identity. A hit must be independently resolved using allowed inputs; otherwise block the affected scope and route it for rewrite by a different author.
