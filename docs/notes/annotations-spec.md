## Model and rendering contract

- New UI marks have a unique `markId` UUID assigned at placement. Their owning `page.id` is distinct. `mark` accepts legacy ID-less values without changing their shape. Selection is a transient mark ID, never a history entry. Native PDF page content isn't selectable this way.
- Text: `kind,text,x,y,angle,size,color`; image: `kind,x,y,angle,width,height,image` (normalized URL, MIME, aspect ratio and typed bytes); ink/highlight: `kind,points:[[x,y],...],size,color`. Coordinates are unrotated PDF user-space positions. Text uses the baseline; image uses its displayed top left. `viewer.point` uses PDF.js viewport inversion, including rotation and page origin. Only the active page has editing geometry.
- `edit(state,{type:'editMark',id:pageId,markId,change})` calls pure `transformMark(mark,change)`. Operations are `translate` (`dx,dy` in PDF units), `scale` (`factor` about the first point or anchor) and `style` (`size` or `color`). `removeMark` takes the same two identities. Moves and scales map actual path points; image scaling preserves aspect. Inserts detach caller data via structured clone. Old snapshots share only unchanged fields, including existing image payloads.
- `createViewer.paint` draws each mark through a local `append(node)` that attaches its ID and measures the actual selected SVG element's bounds. For a new geometry, use one SVG element per mark or extend group hit dispatch to resolve the owning element. Add the render case **before** generic `points` handling. Shapes with ordered PDF points inherit translation and uniform scale; implement shape-specific geometry in `transformMark` if a different representation is chosen. Keep `markId` stable across style/geometry edits.

## Gesture and keyboard ownership

- On pointer down, `pageGestures` checks tagged mark geometry/handles before tap placement, touch pan, immersive view or stroke creation. `beginEdit` switches to selection and returns a pointer owner with `move`, `finish`, `cancel`. The preview transforms the start snapshot; only a completed nontrivial edit calls `session.apply`. Second touch, pointer cancellation, capture loss, rerender or window blur cancels the preview. Pinch remains page-owned. Do not add competing placement listeners for future tools on captured edits.
- Fit-relative SVG viewport dimensions correspond to CSS pixels, independent of raster/device scale. Both rounded handle rects are 46 × 46 in this viewport, providing a margin above 44 CSS px after fractional layout. They are redundant pointer affordances for accessible HTML controls, not extra tab stops.
- `#select-tool` lives in `#document-actions`: desktop toolbar / phone More sheet. `#mark-list` selects a page-local item; page focus accepts arrow-key nudge, Delete and Escape. Nudge buttons, color, size and shrink/grow controls use the existing options overlay. Phone permanent chrome and visualViewport code are unchanged. Place cannot add a mark in select mode. Add future palette controls in the document-actions/sheet route, not the phone mode strip.
- D1 does not change any PDF reader/writer. Existing marks still use the original materialized page-content export. Do not infer editable reopen from these APIs. Preserve strict save verification; independently review updated integration hashes at the final stage.

## W-shapes producer handoff (revision 3, 2026-11-20)

Contributor: `work-c972bba2-40dd-4a87-a718-25b072edd66b`, Annotation geometry and PDF appearance architecture. Built on the admitted selection API; this does not change the original authorship or historical D1 outcome. Sources actually used: the local contracts' W-shapes, invariants and D2 sections, the existing model/viewport/export interfaces, and synthetic observations of the bundled libraries. No external implementation or dependency was added.

`src/shapes.js` defines `subtypes`, `isShape(kind)` and `geometry(mark)`. The model stores `{kind, markId, points:[[x0,y0],[x1,y1]], angle, color, size}` on its page. Points are in unrotated PDF coordinates; angle is the view rotation at creation. The first point anchors proportional scaling. Arrows point toward the second. Region underline/strike follow the original visual bottom/middle of the drag, not text selection. Geometry returns an absolute path, ordered quad and stroke-padded rectangle. Viewer projects each path control point; export writes a normal Form XObject appearance with identical geometry (no burned-in duplicate). Standard reader identities in palette order: `/Underline`, `/StrikeOut`, `/Square`, `/Circle`, `/Line`, `/Line`; arrow has `/LE [/None /OpenArrow]`. Both line types have `/L`; markup has `/QuadPoints`.

Use More tools → shape, drag on unoccupied page area, or Place at page center. Width and color apply before or after placement. Existing mark hits take precedence over drawing. Selection/list/handle operations reuse `editMark`/`removeMark`; cancel discards preview. Escape leaves shape mode. No permanent extra phone controls. Select items is in More on phones and the toolbar on desktop. Foreign annotations and the four older flattened types are not imported as editable shapes. As before, thumbnails show the base page, not live overlays.

`openPDF()` retains original `bytes` for binding, and returns optional `clean` working bytes plus `marks` indexed by source page. `pagesFor`/`documentState` and merge accept these optional marks. `unpack()` matches versioned `PaperplaneShapeV1`, subtype and namespaced UUID `/NM`, validates a bounded payload and only detaches recognized page annotations. Original page contents, widgets and unknown annotations are not suppressed. Unreferenced superseded managed dictionaries/appearance streams are removed from the temporary document; shared references are retained. Preview keeps the existing PDF.js annotation mode. `createPDF` uses the clean base for save/copy/draft/extract and adds current page marks exactly once. This is app identity, not a cryptographic signature or a general editor for externally modified annotation metadata.
