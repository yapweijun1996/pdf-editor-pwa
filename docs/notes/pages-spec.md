## Page identities and geometry

Existing source entries retain `{id,source,index,rotation,marks}`. `source` and zero-based `index` identify the PDF.js page used for geometry; `id` identifies the editable page. A blank uses a fresh UUID, `blank:true`, empty marks and its neighbour's effective geometry, including existing crop and rotation delta. Never render/copy its source content or foreign annotations onto it. Its geometry reference remains live through history. Subsequent edits create new entries. No original binding, source bytes or source page proxy are changed by these operations.

`entry.crop`, when present, is `[left,bottom,right,top]` in **unrotated PDF default user-space coordinates**, not displayed points, edges relative to a zero-origin page, or screen pixels. `entryView` in `viewer.js` constructs an independent PDF.js viewport from the crop or source view, source UserUnit, scale and `(source.rotate + entry.rotation) % 360`. Use `viewer.view` to inspect the current page only, after rendering settles. For arbitrary pages use `sources.get(entry.source).pdf.getPage(entry.index+1)`. Source `view` is PDF.js's effective intersection, not a raw MediaBox. PDF-lib `getMediaBox/getCropBox` return x/y/width/height. Blanks get explicit boxes, page rotation and UserUnit. Page marks, including stamp batches, go through the same projection and `writeMark` path as nonblank marks. See [Page stamps](stamps-spec.md) for the batch, geometry, numbering and content export contracts. Source forms/annotations must not be copied to blanks.

Crop dialog SVG uses a snapshot of the rendered page and overlays; inverse SVG screen transform followed by `convertToPdfPoint` maps a drawn rectangle; numeric fields are PDF points (coordinate multiplied by UserUnit). Finite positive boxes must stay within the **current** visible area; undo to expand. Export sets CropBox only, not MediaBox or content removal. This is not redaction. Do not expose the bytes as a secure removal feature.

## History, groups and downloads

`edit(state, action)` remains pure. `blank` takes neighbour `id`, unique `newId`, `after`; `crop` takes `id,box,bounds`; `group` takes `ids,op` (rotate/delete/move), with move `position` the 1-based **final position of the group's first page**. Remove all selected then insert the group in document order in one operation, preserving both relative orders. Earlier/later shifts its starting position by one. Deleting every page is rejected. With no boxes checked, operate on the current page. Checkbox selection is transient and never checkpoints the source. Touch/keyboard controls live inside the Pages panel and Page tools dialog, not a permanent row. A drag to another thumbnail inserts on the far side in the direction of travel. Drag starts on the grip only. Keyboard activation of a grip opens position entry. Other gestures keep platform scrolling. Thumbnails show base content, not live mark overlays, as before.

`splitPlan` takes an expression with semicolon-separated outputs; commas and inclusive page ranges within each output are deduplicated in current document order. Plan captures page IDs and order at preparation; delete a planned page and its plan clears atomically. Undo/redo reuses the exact history state. Explicit individual downloads cannot be undone. `createPDF(sources,state,pages,baseId,true)` creates a standalone derived document, never an original-handle Save transaction. Source exports carry an optional catalog `PaperplaneSplitV1` with zero-based groups for recovery/reopen (remap to the new workspace IDs). Derived outputs omit the plan. Mixed-source/subset export retains the previous fixed-appearance form behavior; whole-base insertion/reordering keeps catalog/field refs and inherited boxes/resources. No password or encryption support.

## Producer observations (synthetic only)

Five mixed-size pages, including a 90-degree page with raw MediaBox `(10,20,300,420)` and CropBox `(30,40,210,330)` (x/y/w/h). Inserting on either side returned six pages; the blank had no text or annotations, the foreign note and base field survived. Drawing on the rotated preview updated numeric width/height, invalid negative width blocked Apply, and applied `(40,60,160,240)` reopened at PDF.js effective `[40,60,200,300]` with unchanged raw MediaBox. Individual `1,3;2-4` outputs reopened at counts 2 and 3 without confirming the original saved. Both readers checked every output page; PDF.js rendered and extracted text, pdf-lib inspected raw boxes/rotation, the unchanged Save validator checked xref/catalog. Observed actual native OPFS draft payload with crop and split plan. History undo matched the prior state by deep equality.

Chromium desktop and WebKit touch emulation exercised selection of pages 1 and 3, group operations, single-step undo and keyboard position. Moving to 4 produced 2,4,5,1,3; delete produced 2,4,5. On 390x664 the closed stage was 390x576; grip and checkbox were 44×44. Touch-pointer sequences on the thumbnail body versus grip left 1,2,3,4,5 versus 2,1,3,4,5; scrolling the strip 112 CSS pixels kept the order. Escape, blur, pointer cancellation and a second pointer suppressed the drag commit. Scratch probe `/tmp/pages-6074-proof.mjs` and final log `/tmp/pages-6074-final.log` are producer observations, not independent tests. No physical device or full accessibility audit. Final README, regression matrix and independent review are separate.
