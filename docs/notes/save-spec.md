# Save specification mapping

Goal `6638c3e8-7b45-41da-ac7e-331670aece32` revision 4 retains the original S1–S4 and adds the QA1 repair brief. The repair base is `ccbd98ebfe3a02f591a2217f64af249fa9185f1e`, whose tree matches the failed QA1 topic. The older copy-only rule is superseded only for a file explicitly opened through a connected picker handle. Input, drop and launch association remain copy-only. The repair does not authorize a push or require real-device owner acceptance.

- **S1:** Check the intended standalone PDF before opening the original writer: final EOF and `startxref`, cross-reference table and trailer or cross-reference stream, catalog and page count. A size/mtime/SHA-256 comparison detects external changes. Overwrite uses the latest observed original bytes as its backup; the journal publishes backup metadata only after readback verification. The app checks the written file’s SHA-256 and repeats the structural and semantic checks. Failed verification triggers attempted rollback from the verified raw backup regardless of whether the original itself satisfies the export check. Incremental and hybrid cross-references are outside the structural check’s scope. App locks and rechecks are not an OS-level compare-and-swap.
- **S2:** Unconnected documents advertise copy mode. The prepared-PDF link is not a download link. Sharing requires file-share capability and a separate gesture; the user, not the app, confirms that a copy was saved.
- **S3:** The dirty guard and periodic OPFS snapshots are separate from saving the original. Recovery requires an explicit choice and restores materialized PDF content, not undo history. Versions and drafts use IndexedDB metadata and verified OPFS bytes; original permission is queried on recovery and requested on a save or restore gesture.
- **S4:** The Node, desktop and phone regression suites were not changed for this repair. Server-stopped offline testing includes the save module. The README lists, but does not claim, native-device checks.
